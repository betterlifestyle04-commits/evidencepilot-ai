# EvidencePilot — Nebius / NVIDIA / Tavily feedback for hackathon submission

This is a **draft based on implemented repository behavior**, not testimony about personal feelings or a formal benchmark. **Read and edit it before posting on Devpost.** The hackathon explicitly requires feedback on the Nebius and NVIDIA tools used, and offers a bonus award for valuable feedback.

## Nebius Token Factory

**What we used:** The OpenAI-compatible chat completions API at `https://api.tokenfactory.nebius.com/v1/chat/completions` with server-only authentication; model `nvidia/nemotron-3-super-120b-a12b`. It runs claim extraction, Deep Investigation research plans, claim-by-claim assessment and cautious rewriting where supported.

**What worked in our implementation:** A single JSON-speaking inference integration supports multiple distinct stages of the research workflow. A real deployed example completed both Quick Check and Deep Investigation; those limited tests established live connectivity and structurally valid responses, **not** correctness across claims or measured reliability.

**What needed defensive engineering:** The application checks model availability, validates JSON shape and source relationships, applies provider timeouts and supports a structured-output format fallback for provider 400 responses. A browser-visible partial result or an explicit failure is preferable to inventing a citation or silently returning a truncated rewrite.

**Actionable recommendation to Nebius:** Provide prominent per-model structured-output compatibility information, predictable error classifications, and minimal working request/response examples for each NVIDIA Nemotron model. Clear statements of token limits and transient-failure behavior would help developers design bounded, reliable user workflows.

**Onboarding reflection:** We built a live model-catalog and JSON-compatibility probe to confirm whether the configured model could be used. Review this statement with your actual account onboarding experience; do not assert specific onboarding delays or support issues you did not experience.

**Would we use it again?** Potentially yes for open-model, server-side applications that need explicit model selection and controllable AI stages, with application-level validation and rate limiting. Further production use would require broader performance and quality evaluation.

## NVIDIA Nemotron 3 Super

**What we used:** `nvidia/nemotron-3-super-120b-a12b` through Nebius Token Factory. Quick mode uses the model for claim extraction, evidence assessments and rewriting; Deep mode adds per-claim research planning and can trigger Tavily follow-up searches when retrieval is weak.

**Observed strength:** The orchestration supports structured tasks rather than a generic chatbot answer and can attach per-source relationship descriptions to a report. The application still must enforce citation provenance and check model output for consistency.

**Observed limitations / feedback:** Model output alone is not source authentication or factual truth. We needed bounded input/output, source-index mapping and explicit `insufficient_evidence` safeguards so incomplete or inconsistent citations are not shown as confident proof. A declared JSON schema or known structured-output limitations would reduce defensive fallback complexity.

**Recommended improvement:** Publish stable structured-output support and demonstration datasets that evaluate source-faithfulness, temporal reasoning, uncertainty calibration and multilingual evidence assessment. We **do not claim measured performance improvements or comprehensive language coverage**.

## Nebius AI Cloud

**Not used.** The hosted frontend and server routes run on **Vercel**. The hackathon's Nebius requirement is met through **live Nebius Token Factory inference calls**. Do not say you used Nebius AI Cloud, DevPods, Serverless Jobs or Serverless Endpoints if you did not.

## Tavily Search

**What we used:** Live search requests that return actual pages and excerpts for each extracted factual claim. Deep mode can make a bounded second search when the first results are weak.

**What helped:** Real result URLs allow EvidencePilot to display a traceable trail instead of accepting arbitrary links generated by the language model. Search results support a practical end-to-end investigative workflow.

**What needs work / recommendation:** Search snippets can be incomplete, time-sensitive or tangential to a claim, so **URL provenance is not proof**. Better indicators for source update dates, canonical page identity and primary documentation would improve downstream assessment. We've implemented duplicate handling, URL safety checks and conservative no-proof fallbacks.

**Avoid claiming:** Tavily independently fact-checks the retrieved websites, our ranking algorithm proves authority, or every source was manually inspected.

We would consider this stack again for a bounded open-model research assistant, after deeper real-world quality evaluation.
